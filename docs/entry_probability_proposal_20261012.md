# Предложение: вероятность пригодности точки для входа

Статус: постановка задачи и CPU-аудит разметки. Обучение новой модели или RL не запускалось. Это отдельная гипотеза после этапа 2, а не автоматический переход к этапу 3 старого curriculum.

## Что хотим узнать

Выбираем вариант пользователя №3: оценивать качество входа LONG и SHORT. Разворот и ослабление движения могут объяснять удачный вход, но для первого опыта не требуют отдельной, неоднозначной разметки экстремумов.

Конкретный вопрос: «Если открыть сделку после текущей закрытой свечи, какова вероятность достижения +2R раньше −1R в следующие 120 минут?» Слово «вероятность» относится к будущему исходу сделки при заданных правилах, а не к частоте выбора действия агентом.

- Сигнал каждые 5 минут, только после закрытия M1/M5, доступных на этот момент.
- Вход: следующий M1 Open как приближение доступного исполнения. Для проверки торговли нужны задержка, bid/ask, комиссии и проскальзывание.
- R: среднее True Range последних 14 полностью закрытых M5 свечей. Используем именно простое среднее, фиксируем R на момент входа. Это исходная гипотеза масштаба, а не оптимум, найденный перебором.
- Тейк +2R, стоп −1R; срок 120 минут. После проверки календаря данных — также закрытие до конца разрешённой сессии.
- По истечении срока закрываем по доступной цене. Timeout — не обязательно нулевая прибыль.
- Вход с риском, малым относительно издержек, может быть экономически бессмысленным. Правило допустимого отношения издержек к R нужно определить с реальными условиями исполнения; сейчас они неизвестны.

Для каждой стороны прогнозируем три исхода: TP, SL, timeout. Два распределения по три вероятности; сумма внутри каждого равна 1. Это не предположение статистической независимости сторон. Обе стороны могут оказаться плохими. При одинаковом входе и симметричных правилах +2R/−1R оба TP одновременно невозможны; проверяем согласованность прогнозов, в том числе p(TP_LONG)+p(TP_SHORT) <= 1. При необходимости совместная голова по допустимым парам исходов обеспечит это структурно.

Если первый бар касается обеих границ, M1 не устанавливает порядок касаний. Храним флаг неоднозначности. Для первого консервативного обучения такой исход можно определить как SL, явно назвав оцениваемое событие «успех по консервативным правилам M1». Проверяем результат также при противоположном порядке касаний. Точную вероятность исполнения по тикам без тиков эти правила не дают. При гэпе через стоп фактическая потеря может быть больше 1R; расчёт прибыли использует цену исполнения, а не всегда −1R.

## Связь с преимуществом в торговле

Для упрощённого исполнения ровно по границам, в единицах R:

    E = 2*p_TP - p_SL + p_timeout*E[r_timeout | timeout, inputs] - costs/R

Условный результат timeout нужно оценить отдельно или вместо точечной оценки использовать консервативную границу. Для живого выбора входа нельзя подставлять будущую фактическую прибыль timeout. При гэпах/издержках, зависящих от исхода, нужны соответствующие условные выплаты.

Без timeout и издержек порог безубыточности при +2R/−1R равен 1/3. Поэтому высокая доля побед сама по себе не критерий. Нужны положительная ожидаемая прибыль после издержек, достаточно наблюдений и приемлемый риск. NONE получается, когда ни один вход не имеет достаточного преимущества, с порогом, выбранным на validation. Если оба оценены положительно, правило выбора и ограничение на число позиций задаются заранее.

Ни эта формула, ни метка TP не доказывают предсказуемость. Таргет точнее соответствует торговому вопросу, а возможность предсказывать его проверяется вне обучающих периодов.

## «До начала движения»

Таргет качества входа сам по себе допускает вход в уже идущий тренд. Для отдельного опыта именно ДО импульса выделяем причинно определённые состояния сжатия: малая ширина Bollinger и малая реализованная волатильность относительно их прошлой истории, цена ещё внутри предыдущего диапазона. Например, последняя закрытая M5 внутри диапазона предшествующих 12 M5, а ширина Bollinger(20,2) ниже заранее заданного 30-го процентиля прошлых 20 торговых дней. Точные пороги фиксируем до оценки.

Это ограничение по прошлому, а не выбор только тех сжатий, за которыми задним числом случился импульс. Неудачные сжатия обязательно остаются. Такая подзадача — проверяемая гипотеза; аудит ниже не включал этот фильтр. Для сопоставимости показываем и результаты на всех допустимых точках, и на заранее заданном подмножестве. Не выбираем выгодное подмножество после просмотра test.

## Признаки

Сохраняем угловые векторы свечей. Новые признаки — дополнительная ветка, без абсолютных ценовых уровней. Суммируем исходные смещения до atan; High/Low агрегированных свечей получаем через экстремумы пути.

| Блок | Примеры | Смысл |
| --- | --- | --- |
| Движение | Суммы лог-смещений на 5/15/30/60/120 мин, наклоны и изменение наклонов | Направление, ускорение, ослабление |
| Волатильность | ATR/Close, реализованная волатильность, отношения короткого/длинного окна | Масштаб и смена активности |
| Bollinger | Положение относительно средней в единицах sigma, ширина/Close, скорость изменения ширины | Сжатие и растяжение |
| Структура свечей | Тело/диапазон, доли теней, перекрытие свечей, направленное смещение/сумма абсолютных изменений | Одностороннее движение или шум |
| Уровни/POI | Расстояние до прошлого дневного/сессионного High/Low и подтверждённых swing-уровней в ATR, возраст и число касаний | Контекст входа около известных уровней |
| Время | Циклическое время суток/недели, сессия после подтверждения timezone/DST | Изменение рыночного режима |
| Объём/VWAP — условно | Расстояние до session/anchored VWAP в ATR, относительный объём | Только при наличии корректного источника объёма |

Сейчас восстановленный исходный NPZ содержит только OHLC и timestamp. В нём нет ни объёма, ни bid/ask. Нельзя назвать обычную среднюю настоящим VWAP. Tick volume, если найдётся в первоисточнике, — отдельный прокси; биржевой объём GC — другой источник с синхронизацией времени и учётом смены контрактов. Их наличие пока не проверено и не предполагается.

POI должны иметь точное правило. Если swing требует k правых свечей, признак становится известен только через k свечей. Нельзя протягивать назад подтверждённый позднее экстремум, использовать High текущего дня целиком или выбирать anchor по будущему. Для старта достаточно прошлых дневных экстремумов и прошлых rolling-диапазонов.

Производные от тех же OHLC признаки не создают новую информацию. Они могут сделать имеющуюся закономерность доступнее для модели и малого датасета. Полезность блоков проверяем поочерёдным исключением, а не числом индикаторов.

## Вероятности и обучение с нуля / RL

Transformer с нуля подходит для этой постановки. Для вероятностей сначала используем обычный categorical log loss или Brier score по будущим исходам. В среднем эти функции минимизируются истинными условными вероятностями, если представление, данные и оптимизация позволяют их оценить. Это свойство цели, а не гарантия того, что обученная сеть откалибрована.

Не подменяем вероятности весами классов/focal loss ради precision: они могут изменить смысл сырых оценок. Приоритет редких, качественных входов реализуем правилом принятия решения и проверкой калибровки на validation. Калибровку и пороги никогда не подгоняем на test.

RL обучает стратегию действий через награду. Вероятность выбора LONG политикой не является вероятностью успешной сделки LONG. Если действие только «LONG/SHORT/пропуск», а выход всегда фиксирован, это ближе к contextual bandit. В историческом симуляторе без влияния сделки на рынок мы можем вычислить исходы обоих направлений, поэтому скрывать часть известной информации от обучения обычно незачем.

Можно задать RL-награду для выдаваемого распределения p:

    reward(p, outcome) = -sum_k (p_k - 1[outcome=k])**2

Тогда оптимальная оценка — условное распределение исходов. Но это тот же Brier score; доступен прямой градиент, а policy-gradient RL добавляет дисперсию без новой информации. RL имеет отдельный предмет сравнения, когда агент выбирает момент входа/выхода, удержание, размер позиции, стоп/тейк и учитывает состояние портфеля. Такой эксперимент оценивает политику; калиброванный прогноз вероятностей всё равно нужно проверять отдельно. Изобретать RL-оптимизатор для текущего таргета не требуется.

## Минимальный проверяемый эксперимент после обсуждения

1. Зафиксировать источник, время, издержки и правила разметки; визуально показать несколько успешных, плохих и неоднозначных входов до обучения.
2. Одна задача входа, один набор 2R/1R/120 мин. Baseline: постоянные вероятности TRAIN, простая модель на тех же признаках; Transformer с нуля с dropout 25%. Не запускать другие curriculum-этапы автоматически.
3. Разделение только по времени, несколько walk-forward окон. Удалять train-метки, которые заходят в следующий split; калибровке тоже нужен отдельный участок. Не считать перекрывающиеся M1/M5 окна независимыми сделками. Уже просмотренный январь/февраль 2024 не выдавать за новый финальный test.
4. Сначала Brier/log loss и график калибровки, в том числе для больших вероятностей. Затем precision при заданном числе сигналов, покрытия и числа сделок; ожидаемая/реализованная прибыль после издержек при заранее заданном исполнении и числе позиций.
5. Неопределённость оценивать по дням/сессиям, а не iid по перекрывающимся окнам. Проверить неоднозначные бары в двух крайних вариантах. Раздельно показать вклад инженерных признаков и результат на состояниях сжатия.

Успех: выигрыш у baseline по вероятностям и устойчивое преимущество после реалистичных издержек на последующих периодах. Частота положительных меток, красивый loss или единичный удачный месяц этого не устанавливают.
