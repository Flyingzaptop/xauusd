# Формат данных для последующего анализа

Содержимое: все реальные M1 свечи 2021 года. Шаг **1 наблюдённая свеча**,
без пропусков строк, добавления календарных минут или интерполяции выходных.
Это подготовленные признаки, а не результат анализа рынка.

## Организация

- `months/2021-MM.h5`: 12 независимых HDF5 файлов.
- `days.csv`: 365 дат, файл и диапазон строк `[row_start, row_stop)` внутри
  месяца, глобальные границы и число реальных свечей. Закрытые/отсутствующие
  дни имеют пустой диапазон. Индекс не подразумевает заранее известного
  расписания: он описывает фактически имеющиеся записи.
- `dataset.json`: параметры, размеры, версии, SHA256 файлов.
- `protocol.json`: точное определение преобразований и причинности.
- `normalization.npz`: фиксированная медиана мощности каждой компоненты
  за декабрь 2020. Нормы не вычислялись по 2021 году.
- `input_context.npz`: Close и timestamp августа 2020 — декабря 2021,
  исходные номера строк. Достаточен для воспроизведения.
- `input_provenance.json`: происхождение и SHA256 исходного набора.
- `verification.json`: только технические проверки, без рыночных выводов.
- `MANIFEST.json`: размеры и хеши готовых файлов.

В HDF5 все матрицы имеют порядок **time × component**, а не наоборот.
Сжатие gzip/byte shuffle полностью обратимо, Fletcher32 проверяет блоки.
Нет float16/float32, прореживания, clipping, ранжирования частот по результату
или отбора удачных событий.

## Группа `/candles`

| Поле | Тип | Значение |
|---|---|---|
| timestamp | int64 | Сохранённая временная метка, секунды |
| available_timestamp | int64 | timestamp + 60 секунд, после закрытия свечи |
| close | float64 | Реальная цена Close |
| returns_bps | float64 | Разность 10000*log(Close) соседних реальных свечей |
| logprice_relative_bps | float64 | 10000*log(Close) минус значение первой свечи warmup |
| gap_seconds_before | int64 | timestamp−previous_timestamp−60; пауза перед свечой |
| source_row | int64 | Номер строки восстановленного исходного десяти-летнего NPZ |
| global_row | int64 | Номер наблюдённой свечи внутри выходного 2021 года |

Для протокола timestamp трактуется как начало минуты; коэффициент считается
после Close, а не в момент открытия этой свечи. Timezone исходного feed
отдельно не подтверждён: не добавлялись догадки о NY/London, DST или сессиях.
Период 8192 означает 8192 **реальные свечи**, не 8192 календарные минуты.
Ценовые гэпы сохраняются в разности Close, хотя временные паузы склеены.

## Группы преобразований

`/stft_128`, `/stft_512`, `/stft_8192`, `/wavelet_returns`,
`/wavelet_logprice`. Каждая содержит:

| Поле | Тип и форма | Значение |
|---|---|---|
| periods | float64 [components] | Периоды в наблюдённых свечах, по возрастанию |
| reference_power | float64 [components] | Медиана мощности только по декабрю 2020 |
| coefficients | complex128 [time, components] | Исходные комплексные коэффициенты |
| power | float64 [time, components] | abs(coefficients)**2 |
| phase | float64 [time, components] | angle(coefficients), радианы |

В STFT 31/127/2048 компонент соответственно. Для 128/512 оставлены все
FFT-бины k=2…L/4; для 8192 — k=1…2048. Сетка не заменена логарифмическим
подмножеством. Отсюда период 4…L/2 у старых окон, 4…8192 у нового. Бин k=1
нового окна содержит только один цикл на окно; это не свидетельство
надёжно установленного цикла.

STFT: из каждого окна `[t-L+1,t]` вычитается его собственное среднее,
умножается Hann(sym=False), затем считается rFFT. Текущая свеча уже закрыта.
Частоты, фазы, окна или нормы не подбирались по будущему результату.
Коэффициенты сохранены без амплитудной/PSD-нормировки, как в дневном примере;
мощность разных окон нельзя напрямую сравнивать без соответствующей
нормировки. Внутри выбранного окна reference_power позволяет получить
относительную шкалу без изменения исходных коэффициентов.

Для Morlet сохранены прежние 48 периодов 4…512 и добавлены 27 до 8192.
Номинальные периоды не являются заявлениями о физических циклах рынка.
Конечный причинный kernel имеет лаги `0…ceil(8*period)`, Gaussian envelope
`exp(-(lag/period)**2/1.5)`, комплексный carrier `exp(i*2*pi*lag/period)`,
поправку нулевого DC и L2-нормировку. Формула:

    W(t,p) = sum(g_p(lag)*signal(t-lag))

Это **односторонний Morlet filter bank**, не стандартная симметричная CWT.
Не требуется сдвигать коэффициенты на будущее ради доступа: они уже
посчитаны только из доступной истории. Длинный масштаб естественно
смешивает много прошлых свечей; его фаза не является гарантированным
прогнозом актуального движения.

## Производные при чтении

Загрузчик может вычислить без потери исходных данных:

    relative_power_db = 10*log10(max(power,1e-20)/reference_power)

Фаза STFT отсчитана от начала локального окна. `phase_at_end` добавляет
`2*pi*(L-1)/period` и сворачивает угол в [-pi,pi). Это фаза продолжения
соответствующей гармоники до края окна, а не утверждение о настоящей
мгновенной фазе рынка. Для Morlet `phase_at_end` совпадает с raw phase
с учётом обычного сворачивания угла. Для последующей модели можно явно
вычислить sin/cos фазы; эти производные не меняют исходные коэффициенты.

## Использование

`experiments/spectral_year/dataset.py` предоставляет `SpectralYear.load_day`
и `iter_blocks`. Можно выбрать методы, поля и диапазон периодов. Для целого
года используйте поток блоков, не загрузку десятков гигабайт целиком.

Подготовка не задаёт train/valid/test, торговые таргеты, пороги сигналов,
качественные/плохие режимы или гипотезы о доходности. Такие решения и
анализ оставлены на следующий запрос пользователя.
