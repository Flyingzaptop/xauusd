# Sequential teacher v4 — реализация с обязательными проверками

Все дорогие запуски заблокированы, пока не пройдены проверки. GPU автоматически не создаётся.

## Изменённая механика

`environment.py`: единый semi-Markov симулятор. WAIT длится минуту; вход занимает позицию до фиксированного выхода. Стоимость — round-trip на одну унцию, параметр задаётся явно. Награда фиксированного входа известна после выхода, в TD используется gamma^duration. При gamma=1 все денежные результаты имеют одинаковую временную ценность; это текущая база.

Сессия объявляется заранее. В конце нет решений и нулевых сделок. Отсутствующая котировка выхода означает неоценимый эпизод; вход не запрещается по будущим пропускам, эпизод не удаляется из среднего. Пропуски mark-to-market отмечаются отдельно; неполная просадка не выдаётся за точную. PnL фиксируется на выходе, equity строится поминутно по доступным Open. Для исполнения на реальном счёте нужны bid/ask, проскальзывание и валидированный календарь.

`learning.py`: настоящий последовательный PPO с value/GAE по длительности перехода. Вся денежная награда делится на фиксированные $10 только для масштаба оптимизации; отчётность остаётся в долларах. Это объявленный масштаб, не подбор по тесту. Teacher score используется как uncalibrated reward `2*s-1`, а не вероятность победы. Энтропия фиксирована 0.01 для малого smoke-test; её влияние теперь проверяется на известных задачах.

`meta.py`: outer REINFORCE учителя. Только оценка реально выбранной стороны получает credit. Каждый пробный ученик создаётся заново с одинакового начального seed; кандидат после обновления действительно обучает проверочных учеников. Для итогового сравнения выделены другие seeds. Teacher sampling используется последовательно и во время обучения, и у новых учеников; dropout выключен в этих малых Transformer. Случайности ученика и teacher sampling разделены. Это проверяемый прототип, а не обещание эффективного meta-RL.

## Команды

Используется `/workspace/colab-tools/bin/python`.

- `python test_environment.py` — механика, семантика времени, пропуски, закрытие и GAE.
- `python run_gates.py` — 4 задачи × 3 seed, новые процедурные тестовые эпизоды. Два блока Transformer, width32; большой моделью не подменяем проверку механики.
- `python meta.py` — малый синтетический эксперимент передачи пользы учителя новым ученикам, плюс initial/constant/shuffled/money контроли.
- `python gates.py --stage real_pilot` — проверка допуска. Непройденный gate возвращает ненулевой код.
- `python real_data.py --raw-dir DIR --config windows.json --out PANEL` — небольшой панельный dataset из ВСЕХ исходных 222 parquet. Отсутствующие инструменты не подменяются нулями.
- `python pilot.py --panel PANEL --out OUT --mode money` — реальный последовательный пилот только после прохождения gates. `--gold-only` делает явно отмеченную абляцию, `--mode learned --teacher ...` требует совместимого обученного учителя.

## Данные

Конфигурация windows содержит заранее объявленные UTC-окна стратегии и chronological train/dev/test. Между split выдерживается 1560 минут. Пример элемента: `{"date":"2022-03-07","open":"08:00","close":"18:00","split":"train"}`. Выходные/праздники исключаются по известному календарю, не по будущей прибыли или наличию будущих котировок. Эти окна не выдаются за календарь брокера.

48 causal features каждого инструмента берутся из сохранённой реализации v3, затем asinh и finite masks. Модель получает только t-8..t-1; абсолютные цены не подаются. Короткий контекст — свойство малого пилота, не финальная архитектура. Для реального учителя разрешён будущий путь, ученик его не видит.

`diagnostics.py` предоставляет полные mean/variance и абляции прошлого/будущего на переданных тензорах. Старые v2/v3 требуют своих 222×120×96 входов и оригинального model.py; новые короткие входы им не подсовываются. Полные старые реальные входы после выключения VM заново не восстановлены.

`reward_audit.py` оценивает net, mark-to-market DD, недельные результаты и чувствительность к явным risk preferences. Количество сделок не награждается само по себе. Базовое денежное objective не объявляется окончательным решением задачи стабильности.

## Границы доказательства

Положительные синтетические задачи доказывают исправность части механики, а не наличие преимущества в рынке. Неуспех meta-gate запрещает масштабирование учителя. Уже просмотренные периоды рынка не становятся новыми независимыми тестами. Для большого запуска нужна дополнительная real-pilot проверка и протокол ещё не просмотренного периода.

## Дополнительный вариант meta-gradient

`python meta_gradient.py --task direction|wait|cross_market` запускает отдельный эксперимент. Здесь learner использует точный policy gradient ожидаемого возврата, учитель получает производную через три обновления learner. Динамическое программирование учитывает WAIT/OPEN и занятость позиции. Меток желаемого действия нет. Это другой learner protocol, чем PPO; его учитель не допускается к PPO автоматически.

`python test_meta_gradient.py` проверяет точное ожидание и внешний градиент конечными разностями. `python gates.py --stage exact_pilot` требует успешного переноса на всех трёх задачах. Сейчас этот допуск не пройден из-за cross_market.

`python check_market_execution.py` проверяет только исполнение на 9 заранее объявленных окнах реальных котировок XAUUSD. Это не тест прибыльности стратегии.

`python finalize_report.py` заново запускает механические тесты и формирует отчёт/реестр доказательств. Научные результаты содержат SHA256 исходников, снятые при старте эксперимента. Повторное формирование отчёта не превращает устаревшие результаты в действительные.
